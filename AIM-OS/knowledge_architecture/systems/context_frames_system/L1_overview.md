# L1 Overview: Context Frames System

## Purpose
The Context Frames System provides a structured, three-layer context management approach that ensures every file, folder, and system in AIM-OS has appropriate context information available for safe and informed decision-making.

## Core Functionality

### Context Frame Layer (Mandatory)
- **Always Loaded**: Small, mandatory context summaries for every system component
- **Pre-flight Checklist**: Essential information needed before any operation
- **Identity Card**: System identity, purpose, and critical constraints
- **Blast Radius**: Impact assessment and risk boundaries
- **Open Wounds**: Known issues and areas requiring attention

### Context Mesh Map Layer (Network-Aware)
- **Dependency Declaration**: What other systems are context-critical for mutations
- **Constraint Propagation**: Vows and constraints that must be pulled in
- **Network Topology**: Visual representation of system relationships
- **Impact Analysis**: Understanding of change propagation through the system

### Deep Context Appendix Layer (Comprehensive)
- **Historical Mind**: Complete design history and rationale
- **Decision Context**: Why decisions were made and what alternatives were considered
- **Incident Documentation**: Past problems and their solutions
- **Frontier Ideas**: Future possibilities and research directions

## Integration Points

### With L0-L4 Documentation System
- **Context Bootloading**: Provides context for understanding L0-L4 documentation
- **Documentation Integration**: Context frames reference relevant documentation
- **Quality Validation**: Ensures context information is complete and current

### With System Maps
- **Topology Integration**: Context mesh maps integrate with system topology
- **Dependency Tracking**: Tracks cross-system dependencies and constraints
- **Map Validation**: Ensures system maps reflect current context relationships

### With Development Workflow
- **Pre-edit Context**: Provides context before making changes
- **Change Impact**: Shows impact of changes on other systems
- **Decision Support**: Provides historical context for decision-making

### With MCP Tools
- **Context Storage**: Stores context information in persistent memory
- **Context Retrieval**: Retrieves relevant context for operations
- **Context Synthesis**: Synthesizes context from multiple sources

## Key Benefits

### Context Continuity
- **No Context Loss**: Ensures context is always available when needed
- **Information Preservation**: Maintains institutional knowledge
- **Decision History**: Preserves reasoning behind past decisions

### Safe Operations
- **Informed Decisions**: Complete context for safe decision-making
- **Risk Awareness**: Clear understanding of impact and constraints
- **Dependency Visibility**: Know what affects what before making changes

### Efficiency
- **Rapid Onboarding**: Quick understanding of any system
- **Lazy Loading**: Load only what's needed when it's needed
- **Structured Access**: Organized context for easy navigation

### Quality Assurance
- **Consistency**: Standardized context format across all systems
- **Completeness**: Ensures all necessary context is available
- **Validation**: Regular validation of context accuracy and currency
