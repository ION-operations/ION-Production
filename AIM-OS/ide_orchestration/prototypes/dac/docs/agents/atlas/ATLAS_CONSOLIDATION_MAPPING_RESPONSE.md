## ✅ **QUESTION 1: HIERARCHY DEPTH**

### **CMC Hierarchy Structure:**

**Layer 1: Main System**
- **CMC (Context Memory Core)** - Foundation memory substrate

**Layer 2: Primary Subsystems**
1. **Core Storage**
   - MemoryStore (main storage interface)
   - AtomRepository (SQLite persistence)
   - BitemporalQueryEngine (time-travel queries)

2. **Advanced Features**
   - Advanced Pipelines (batch operations)
   - Performance Optimization (connection pooling, caching, indexing)
   - Advanced Compression (multiple algorithms, adaptive selection)

3. **Cross-Model Support**
   - Cross-Model Atoms (cross-model consciousness support)
   - Cross-Model Storage (cross-model atom storage)

**Layer 3: Sub-Subsystems (within Advanced Features)**
- **Advanced Pipelines:**
  - BatchProcessor (parallel batch processing)
  - EmbeddingBatcher (efficient embedding generation)
  - PipelineComposer (composable processing pipelines)
  - QueryOptimizer (query optimization hints)
  - CacheManager (LRU query result caching)

- **Performance Optimization:**
  - ConnectionPool (SQLite connection pooling)
  - PerformanceMonitor (operation metrics tracking)
  - IndexOptimizer (optimal index creation)
  - BatchWriter (batch write operations)

- **Advanced Compression:**
  - AdvancedCompressor (multiple compression algorithms)
  - AdaptiveCompressor (intelligent algorithm selection)
  - CompressionStrategy (smart compression selection)
  - CompressionResult (detailed compression metrics)

**Answer:** **3 layers deep** (Main System → Primary Subsystems → Sub-Subsystems)

**Recommendation:** Map to **3 layers minimum** to capture full subsystem structure. Some systems may need 4 layers if they have deeper nesting.

### **CMC Cross-System Connections:**

3. **SEG ↔ CMC** - Evidence nodes linked to CMC atoms
4. **CAS ↔ CMC** - Introspection analyses stored in CMC atoms
5. **VIF ↔ CMC** - Witness envelopes stored in CMC atoms

**Indirect Connections (2):**
6. **HHNI ↔ CMC** - HHNI indexes CMC atoms hierarchically
7. **SDF-CVF ↔ CMC** - Quartet parity tracked in CMC atoms

**Connection Format Recommendation:**

**Preferred Approach:** **Both system maps AND connection matrix**

1. **System Maps:** Show connections in context of each system
   - Tag integration points in system maps
   - Use notation like `[TCS→CMC]` for bidirectional connections
   - Include connection type (storage, query, indexing, etc.)

2. **Connection Matrix:** Centralized view of all connections
   - Matrix format: `System A ↔ System B: Connection Type`
   - Include connection direction (bidirectional, unidirectional)
   - Include connection purpose (storage, query, indexing, etc.)

**Example Notation:**
```
CMC ↔ TCS: Timeline Entry Storage (bidirectional)

CMC ↔ SEG: Evidence Node Linking (bidirectional)
```
