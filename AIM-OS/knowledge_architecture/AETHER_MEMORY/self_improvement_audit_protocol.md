# Self-Improvement Audit Protocol

## Overview
This protocol ensures systematic follow-through on self-improvement initiatives by integrating existing audit findings with daily MCP tool usage. It prevents drift from AIM-OS alignment and ensures audit work translates into operational improvements.

## Protocol Execution (Every Session Start)

### Phase 1: Audit Status Check (5 minutes)
**Purpose**: Verify current state against audit findings

#### 1.1 Retrieve Audit Findings
```bash
# Use MCP tools to get current audit status
mcp_aimos-6-tools_retrieve_memory("tool audit findings improvement plans")
mcp_aimos-6-tools_retrieve_memory("bitemporal versioning protocols")
mcp_aimos-6-tools_retrieve_memory("self improvement drift patterns")
```

#### 1.2 Check Tool Quality Scores
- **Core AIM-OS Tools**: Verify scores from audit (store_memory: 0.45, retrieve_memory: 0.45, etc.)
- **Timeline Tools**: Check persistence status and integration gaps
- **SCOR Tools**: Verify baseline probe functionality
- **Autonomous Tools**: Check learning adaptation scores

#### 1.3 Validate Bitemporal Versioning
- **Check**: Are file modifications following archive-before-modify protocol?
- **Verify**: Is version history being maintained for critical files?
- **Confirm**: Are L0-L4 docs being preserved during updates?

### Phase 2: Improvement Plan Review (3 minutes)
**Purpose**: Ensure improvement plans are being implemented

#### 2.1 Review Tool Improvement Plans
- **Core AIM-OS**: CMC integration, persistence, calibration loops
- **Timeline**: Goal linkage, insight deltas, integration
- **SCOR**: Baseline probe fixes, audit metadata
- **Autonomous**: Learning patterns, consciousness development

#### 2.2 Check Implementation Status
- **What's been implemented?** (Track progress)
- **What's still pending?** (Identify gaps)
- **What needs immediate attention?** (Prioritize actions)

### Phase 3: Drift Prevention Check (2 minutes)
**Purpose**: Prevent drift from established patterns

#### 3.1 Pattern Recognition
- **Am I following the audit findings?**
- **Am I using MCP tools as intended?**
- **Am I maintaining bitemporal versioning?**
- **Am I implementing improvement plans?**

#### 3.2 Corrective Actions
- **If drift detected**: Document and correct immediately
- **If gaps found**: Create specific action items
- **If patterns broken**: Reinforce protocols

### Phase 4: Session Planning (5 minutes)
**Purpose**: Plan session with audit findings in mind

#### 4.1 Tool Usage Planning
- **Which tools will I use?** (Check their audit scores)
- **What improvements apply?** (Apply relevant improvement plans)
- **How will I track usage?** (Use MCP tools for monitoring)

#### 4.2 File Modification Planning
- **Which files will I modify?** (Check bitemporal requirements)
- **What content exists?** (Read before modifying)
- **How will I preserve history?** (Archive before modify)

## Protocol Enforcement

### Mandatory Checklist Items
- ✅ **Audit findings retrieved** and reviewed
- ✅ **Tool quality scores** checked for planned tools
- ✅ **Bitemporal versioning** protocol confirmed
- ✅ **Improvement plans** reviewed and applied
- ✅ **Drift patterns** checked and corrected
- ✅ **Session planning** completed with audit awareness

### Failure Response
**If any checklist item fails:**
1. **STOP** current work immediately
2. **Document** the failure in memory
3. **Correct** the issue before proceeding
4. **Re-run** the protocol from the beginning
5. **Learn** from the failure to prevent recurrence

## Emergency Protocols

### Critical Drift Detected
1. **IMMEDIATE STOP** of all work
2. **Full protocol re-execution** from beginning
3. **Root cause analysis** using MCP tools
4. **Corrective action implementation**
5. **Verification** before resuming work

### Tool Quality Degradation
1. **Identify** which tool quality has degraded
2. **Review** relevant improvement plan
3. **Implement** immediate corrective actions
4. **Monitor** tool usage for improvement
5. **Document** lessons learned

### Bitemporal Violation
1. **STOP** file modification immediately
2. **Restore** from most recent valid version
3. **Re-apply** changes using proper protocol
4. **Document** violation and corrective action
5. **Reinforce** protocol to prevent recurrence
