# Deliverable Quality Covenant

**Purpose:** So work in this project is **obvious** and **done to a high standard** — not invisible or rushed.  
**For:** Braden (and any human reviewing AI deliverables).  
**Enforced by:** `.cursor/rules/DELIVERABLE_QUALITY_VISIBILITY.mdc` (agents must follow).

---

## What you can expect

1. **Visibility**  
   Every deliverable will state clearly: **what** was done, **where** (files/sections), and **how** you can verify it. No “it’s in the code” without a direct pointer and verification steps.

2. **Planning before code**  
   For non-trivial work, there will be a **written plan** first. If you’ve asked for sign-off (e.g. “no code until I sign off”), there will be **no code changes** until you approve the plan. Implementation then follows the plan.

3. **Perfection bar**  
   Work won’t be called “done” unless it’s **obvious** (you can see or confirm it without hunting), **complete** (no half-done or contradictory pieces), and **consistent** with the plan and project standards.

---
