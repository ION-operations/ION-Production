# PL/I — Identity

**Kind:** **Procedural, imperative** programming language family, originally **IBM-led** (1960s onward), standardized (e.g. ANSI X3.53-1976 per secondary summaries), aimed at **scientific, engineering, business, and systems** programming in one language surface (`DOCUMENTED`, `src-wiki-pl-i`, `src-ansi-pl-i-ref`).

**Pronunciation / spelling:** “Programming Language One”; often written **PL/I** or **PL/1** in informal text (`DOCUMENTED`, `src-wiki-pl-i`).

## Boundaries

- **Not** a single compiler binary — **implementations** span IBM mainframe products, Multics-era compilers, and others (`HISTORICAL` / vendor-specific — tier per implementation doc).  
- **Not** PL/M, PL/S, PL.8, or Rexx — related but **distinct** lineages (`DOCUMENTED`, `src-wiki-pl-i-influenced`).

## Why this system matters

- **Convergence language** design: unify Fortran/COBOL/ALGOL-class concerns on **System/360-class** platforms (`HISTORICAL`, `src-wiki-pl-i-history`).  
- Influenced **systems** and **data** programming culture (e.g. Multics exposure to early manuals — `HISTORICAL`, `src-wiki-pl-i-multics`).  
- Example of **large** standardized language with **exception handling**, rich **data types**, and **separate compilation** goals (`DOCUMENTED`, `src-wiki-pl-i-summary`).

## What this system teaches the atlas

- How to separate **language standard** from **compiler product** when tiering claims.  
- How **IBM + SHARE** governance shaped a multi-domain language (`HISTORICAL`).
