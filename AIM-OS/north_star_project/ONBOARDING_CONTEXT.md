## 🔧 **ORCHESTRATION ARCHITECTURE**

### **Machine-Executable Chain:**

**Chain Specification (`ChainSpec.yaml`):**
- YAML-based executable spec (not prose!)
- 40 chapter nodes with full metadata
- Dependency graph computable
- Status trackable in real-time
- Tier A source requirements enforced
- Quality gates defined per chapter

**Quality Policy (`gates.json`):**
- 4 gates per chapter:
  1. **Pre-Chapter:** Dependencies, Tier A sources, VIF ≥ 0.70, outline
  2. **Word Count:** Target ±10%, subsection balance
  3. **Technical:** Examples run, math verified, no fake features, sources cited
  4. **Integration:** No contradictions, terms consistent, crossrefs valid

**Orchestration Engine (`run_chain.py`):**
- Loads chain spec and policy
- Validates dependencies before starting
- Checks Tier A source availability
- Runs VIF confidence checks
- Executes all quality gates
- Tracks progress and status
- Generates ready-to-start lists

### **Key Features:**

**1. Authority Enforcement (ChatGPT Blueprint):**
- Each chapter declares Tier A sources
- Fails fast if Tier A missing
- Forces grounding in authoritative docs
- Prevents hallucination

**2. Confidence κ-Gating (VIF):**
- VIF checks confidence < 0.70
- Routes to ARD research automatically
- Blocks merge if low confidence
- Ensures quality

**3. Evidence Ledger:**
- `evidence.jsonl` per chapter
- Every claim → citation token
- SEG can synthesize across chapters
- Enables "no contradictions" check

**4. Contradiction Police (SEG):**
- Glossary drift detection
- Numeric mismatch checking
- Dangling cross-reference detection
- SEG-based claim conflict analysis

**5. Merge Policy:**
- No merge without: deps ✅ + tierA ✅ + κ≥0.70 + 4 gates ✅ + evidence non-empty
- Requires manager approval
- Prevents low-quality merges
