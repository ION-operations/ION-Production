## 📚 QUICK REFERENCE

### **What is SAM?**

**SAM (System Anatomy Mapping)** is a compiler-based documentation methodology that:
- Documents systems with mathematical precision
- Optimizes for both AI and human consumption
- Provides cryptographic verification of correctness
- Applies universally to any system type

### **Core Concepts**

1. **Compiler Model**: SAM is a compiler (sources → monolith + evidence), not a file system
2. **Three Artifacts**: Canonical sources (truth) + Compiled monolith (distribution) + Build evidence (proof)
3. **Universal Schema**: Five dimensions (Structure, Behavior, Interfaces, Constraints, Evidence)
4. **Tag Governance**: Registry-based tags prevent sprawl
5. **Machine-Parseable**: JSON index for instant retrieval

## 💡 KEY INSIGHTS

### **What Makes SAM Different**

**Traditional Documentation:**
- Files scattered across codebase
- Inconsistent formats
- Becomes stale quickly
- Hard for AI to understand
- No verification

**SAM Documentation:**
- ✅ Compiler-based (sources → artifacts)
- ✅ Universal schema (consistent structure)
- ✅ Living documentation (evolves with code)
- ✅ AI-optimized (RAG-friendly)
- ✅ Cryptographically verified (provable correctness)

### **The SAM Innovation**

**SAM is NOT:**
- ❌ A file format
- ❌ A documentation tool
- ❌ A code generator
- ❌ A version control system

**SAM IS:**
- ✅ A **compiler** (transforms sources into artifacts)
- ✅ A **methodology** (how to document systems)
- ✅ A **standard** (universal schema)
- ✅ An **ecosystem** (sources + monolith + evidence)
