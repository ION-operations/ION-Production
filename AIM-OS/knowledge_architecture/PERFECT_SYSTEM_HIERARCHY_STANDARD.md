## 🎯 **STANDARD OVERVIEW**

The System Hierarchy is **the organizational backbone of AIM-OS** - defining how all systems relate to each other across 6 clear layers, from memory foundation to application integration. This standard ensures clear system organization and guides documentation requirements.

**What Makes System Hierarchy Essential:**
- **Clear Organization** - Know where each system belongs
- **Relationship Understanding** - See dependencies clearly  
- **Documentation Guidance** - Know which systems need maps/indexes
- **Priority Clarity** - Core vs supporting systems clear
- **Evolution Management** - Track system additions
- **Onboarding** - Help new AIs/humans understand structure

## 🔬 **MAINTENANCE PROTOCOLS**

### **Adding New Systems**

**Process:**
1. Classify by layer (1-6)
2. Identify dependencies
3. Determine documentation requirements
4. Create required docs
5. Update hierarchy document
6. Update system maps (affected systems)

**Classification Guide:**
- Layer 1: Stores/synthesizes knowledge?
- Layer 2: Processes/verifies intelligence?
- Layer 3: Orchestrates/plans?
- Layer 4: Meta-cognition/awareness?
- Layer 5: Supports consciousness?
- Layer 6: User-facing/external?
